Add task · keys: pick existing or create new

The add popover gets the same Keys chips as the edit popover. The open question is how to offer the keys and values already used in the plan while still allowing new ones. Sample plan: type (architecture 3, development 6), owner (Jonas 4, Sam 3, Alex 2), team (Frontend 4, Design 3, Core 2).

Recommendation

A · Two-step combobox: pick the key, then pick the value

  • One pattern for both questions. Key and value use the same list: existing entries first (most used on top), and a "+ New …" row at the end that is only highlighted when nothing matches.
  • Clicking is enough, typing is optional. + key → owner → Jonas is 3 clicks. Keyboard: type, ↵, type, ↵.
  • The "new" tag protects against typos. "Jonsa" shows up as new, so it's obvious it doesn't match anything.
  • It scales to many keys or values (the list filters), unlike B. It's also discoverable, unlike C.
  • Same chip in the edit popover, so it can be reused there later.

Open questions

  • Prefill on "+ After"? Copy the predecessor's keys as removable chips. It saves the most clicks, but the user has to notice values they didn't type.
  • Values: plain text only, or show a color swatch for the active "Color by" key (shown in A3)?
