PNG export — proposals

Three button placements, each paired with a different implementation. The demos are real: every export action produces an actual PNG from the chart below (download link + size + timing), so the techniques can be compared on output, not just on paper. Toggle the theme top-right to see how each one handles the CSS-variable colors.

What the PNG must contain

    Exported

  • Bar colors by the active color key — var(--bar-N) resolved to hex
  • Label colors --bar-N-fg (contrast per fill)
  • Legend (value → color), else the colors mean nothing
  • Section column + section durations
  • Axis ticks, gridlines, weekend shading, alt bands
  • Arrows, chevrons, dashed gap lead-ins
  • Title + date range header
  • The full chart, not the scrolled viewport

    • Left out

  • Focus ring, dimming of unselected bars
  • "+ New task" / "+ New section" proposals
  • Connector dots, marquee, cut links, ghosts
  • Pills, popovers, hover card

A · "Download ▾" menu — clone the live SVG + inline computed styles

The existing Download button becomes a split menu (.md / .png / .svg). Export clones the on-screen SVG, copies every element's getComputedStyle (fill, stroke, opacity, font…) into inline styles so the CSS variables and scoped classes survive, draws it on a canvas, then paints title + legend with the canvas API. The chart below has a selected bar on purpose: tick the box off to see what leaks into the PNG.

// utils/exportPng.ts — A
const PROPS = ['fill', 'stroke', 'stroke-width', 'stroke-dasharray', 'opacity', 'font-size', 'font-weight', 'font-family'];
function inlineStyles(src: Element, dst: Element) {
  const s = src.querySelectorAll('*'), d = dst.querySelectorAll('*');
  s.forEach((el, i) => { const cs = getComputedStyle(el);
    (d[i] as SVGElement).style.cssText = PROPS.map((p) => `${p}:${cs.getPropertyValue(p)}`).join(';'); });
}

B · "Export…" dialog — dedicated export renderer (recommended)

A separate Export button opens a dialog with a live preview and a few options. Behind it an <ExportChart> component reuses computeLayout() and emits one clean SVG — title header, section column, timeline, legend — with colors already resolved to literals for the chosen theme. No interaction layers exist in it, so selection state can't leak.

C · One-click camera button — html-to-image library

A camera icon in the view toolbar, right next to the legend: one click saves the PNG (⇧-click could copy it to the clipboard). html-to-image snapshots a DOM subtree — here a wrapper around legend + chart — handling CSS variables, scoped styles and fonts itself. A filter drops interactive nodes. Loaded from esm.sh in this mockup (needs network).

Recommendation: B's renderer, optionally behind A's menu

The export renderer is the only approach where the output can't depend on what's selected or scrolled, and it gives a light PNG for documents while you work in dark mode. If the dialog feels heavy, the same renderer can sit behind the Download ▾ menu with defaults (light, 2×, title + legend) — the dialog can come later.

Open decisions

  1. Default theme: always light (documents/slides) or current?
  2. Button: Download ▾ menu (A), Export… dialog (B), or camera icon (C)?
  3. Clipboard copy in addition to download — wanted?
  4. Very wide plans (month zoom over a year): cap at a max width / scale down, or export as-is?
