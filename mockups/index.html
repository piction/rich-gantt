Principles the designs follow

  • Spatial things stay on the bar. Move = drag the body; resize = drag the end edge (existing). No "move" button.
  • First click focuses, never mutates. Only a focused bar is draggable, so a stray click can't shift the plan.
  • Show consequences before they happen. A move that will cut an after link previews it (red dashed + scissors) during the drag.
  • Undo instead of confirm. Delete/move/unlink are instant with an undo toast; no dialogs.
  • Every action has a key, shown in its tooltip. Mouse-only and keyboard-only both work end to end.
  • Ask only for what can't be inferred. Add-after needs just a name; section, length, position and id default.

Open decisions for you

  1. Delete with successors: successors inherit the deleted task's predecessors (chain stays connected, things slide left) or successors get pinned to their current dates (nothing moves)?
  2. Move a fan-in task (after a b): cut all links (simple, shown) or keep them and only allow moving later (lag) — the format has no lag, so I'd cut all.
  3. New task id: auto-slug from the name (hovercar12) or sequential per section (dev7)?
  4. Edit scope: name + keys + notes in the popover (shown), or name only and "Source" for the rest?
  5. Undo stack: doesn't exist yet. The design leans on it (no confirms). Worth building as part of this feature.
