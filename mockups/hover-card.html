Hover card · showing keys and values properly

Today the hover card renders the whole metadata block as markdown, so keys show up as a plain bullet list. It also uses its own surface (6 px radius, --bg, a different shadow) instead of the --surface, 12 px radius and --shadow of the pill and popovers. All variants below show the keys as structured data from metadata.attrs, render only the notes (the markdown after the keys) as markdown, and use the same surface as the rest of the floating UI.

Recommendation

B · Property list, with the color swatch from C

  • Easiest to scan. Keys line up in one column, values in the other, and Start/End/After use the same grid. One layout for everything, no special cases.
  • Same structure as the edit popover (label → keys → notes), so hovering previews exactly what editing opens.
  • Works with 0 or 8 keys and with long values. A (chips) wraps unpredictably with many keys. C relies on a "type"-like key to look good.
  • Borrow from C: the swatch of the "Color by" value, so the card links visibly to the bar color and the legend.

Applies to all variants

  • Notes clamp at 3 lines with a fade. The full text is in the editor (↵), and the hover card stays a preview.
  • Dates read as days ("Mon 14 Sep"), the same as the tick labels and the add popover, not ISO strings.
  • No metadata: no "No metadata for this task." line. Show the schedule part only, so the card just gets shorter.
  • Same surface as pill/popovers (--surface, --border, 12 px radius, --shadow). The section hover card should get the same treatment.
